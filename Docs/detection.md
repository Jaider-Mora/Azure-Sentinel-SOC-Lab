# Detection Engineering

## Overview

This document describes the detection logic implemented in the Azure Sentinel SOC Lab to identify failed SSH authentication attempts against a Linux endpoint.

The detection process starts with raw Syslog events generated by the SSH daemon and progressively transforms the data into useful security information.

The detection pipeline is:

```text
Syslog
   |
   v
SSH Authentication Failure
   |
   v
Failed SSH Detection
   |
   v
Attacker IP Extraction
   |
   v
GeoIP Enrichment
   |
   v
Attack Aggregation
   |
   v
Geographic Visualization
```

The implementation uses Microsoft Sentinel KQL queries to perform each stage of the detection process.

---

## 1. Failed SSH Login Detection

The first detection identifies failed SSH authentication attempts recorded in the `Syslog` table.

The query analyzes events generated during the previous 30 days and filters events generated by the `sshd` process containing the `Failed password` message.

```kusto
Syslog
| where TimeGenerated > ago(30d)
| where ProcessName == "sshd"
| where SyslogMessage has "Failed password"
| project
    TimeGenerated,
    Computer,
    SyslogMessage
| order by TimeGenerated desc
```

### Detection criteria

The query uses three primary conditions:

| Condition                             | Purpose                                                 |
| ------------------------------------- | ------------------------------------------------------- |
| `TimeGenerated > ago(30d)`            | Limits the investigation window to the previous 30 days |
| `ProcessName == "sshd"`               | Identifies events generated by the SSH daemon           |
| `SyslogMessage has "Failed password"` | Identifies failed password authentication attempts      |

The query returns the event timestamp, source computer, and original Syslog message.

This query establishes the baseline detection for failed SSH authentication.

---

## 2. Attacker IP Extraction

After identifying failed SSH authentication events, the next step is extracting the source IP address from the Syslog message.

A typical event may contain information similar to:

```text
Failed password for invalid user admin from 192.168.1.50 port 54321 ssh2
```

The IP address is extracted using a regular expression:

```kusto
| extend AttackerIP = extract(
    @"from\s+((?:\d{1,3}\.){3}\d{1,3})",
    1,
    SyslogMessage
)
```

The complete query is:

```kusto
Syslog
| where TimeGenerated > ago(30d)
| where ProcessName == "sshd"
| where SyslogMessage has "Failed password"
| extend AttackerIP = extract(@"from\s+((?:\d{1,3}\.){3}\d{1,3})", 1, SyslogMessage)
| where isnotempty(AttackerIP)
| project
    TimeGenerated,
    Computer,
    AttackerIP,
    SyslogMessage
| order by TimeGenerated desc
```

The extracted IP address becomes an indicator that can be used for additional enrichment and investigation.

---

## 3. GeoIP Enrichment

The extracted attacker IP addresses are enriched using the `GeoIP_List` Sentinel Watchlist.

The `ipv4_lookup()` operator is used to match each IP address against the network ranges contained in the watchlist.

```kusto
| evaluate ipv4_lookup(
    _GetWatchlist("GeoIP_List"),
    AttackerIP,
    network
)
```

The resulting data contains geographic information associated with the matched network.

The latitude and longitude values are converted into numeric values:

```kusto
| extend Lat = todouble(latitude)
| extend Lon = todouble(longitude)
```

The query then removes events for which geographic coordinates are unavailable:

```kusto
| where isnotnull(Lat) and isnotnull(Lon)
```

---

## 4. Attack Aggregation

After geographic enrichment, the events are aggregated by attacker IP and geographic location.

```kusto
| summarize FailureCount = count()
    by AttackerIP, Lat, Lon, city, country
```

`FailureCount` represents the number of failed SSH authentication events associated with each source IP within the selected time period.

A human-readable location label is also generated:

```kusto
| extend friendly_location = strcat(city, " (", country, ")")
```

This information is useful for both investigation and visualization.

---

## 5. Geographic Attack Visualization

The final detection query combines the previous stages and renders the results as a geographic map.

```kusto
Syslog
| where TimeGenerated > ago(30d)
| where ProcessName == "sshd"
| where SyslogMessage has "Failed password"
| extend AttackerIP = extract(@"from\s+((?:\d{1,3}\.){3}\d{1,3})", 1, SyslogMessage)
| where isnotempty(AttackerIP)
| evaluate ipv4_lookup(_GetWatchlist("GeoIP_List"), AttackerIP, network)
| extend Lat = todouble(latitude)
| extend Lon = todouble(longitude)
| where isnotnull(Lat) and isnotnull(Lon)
| summarize FailureCount = count() by AttackerIP, Lat, Lon, city, country
| extend friendly_location = strcat(city, " (", country, ")")
| project FailureCount, AttackerIP, Lat, Lon, city, country, friendly_location
| order by FailureCount desc
| render scatterchart with (kind = map)
```

The query produces the dataset used by the SSH Attack Intelligence Dashboard.

## 6. Detection Data Flow

The complete detection process can be represented as follows:

```text
Linux SSH Service
       |
       v
Failed Authentication Event
       |
       v
Syslog Table
       |
       v
Filter sshd + "Failed password"
       |
       v
Extract Attacker IP
       |
       v
GeoIP_List Watchlist
       |
       v
Latitude / Longitude
       |
       v
Aggregate Failed Attempts
       |
       v
SSH Attack Intelligence Dashboard
```

Each stage adds contextual information to the original authentication event.

---

## 7. Detection Output

The final query produces the following fields:

| Field               | Description                                  |
| ------------------- | -------------------------------------------- |
| `FailureCount`      | Number of failed SSH authentication attempts |
| `AttackerIP`        | Source IP extracted from the Syslog event    |
| `Lat`               | Geographic latitude                          |
| `Lon`               | Geographic longitude                         |
| `city`              | GeoIP city                                   |
| `country`           | GeoIP country                                |
| `friendly_location` | Combined city and country label              |

These fields provide the information required by the geographic visualization.

---

## 8. Detection Time Window

The current detection uses:

```kusto
ago(30d)
```

This means the queries analyze events generated during the previous 30 days.

The time window can be modified depending on the investigation requirements.

For example:

```kusto
ago(24h)
```

can be used for a one-day investigation, while:

```kusto
ago(7d)
```

can be used for a seven-day investigation.

The current 30-day window is used as the default configuration for the laboratory.

---

## 9. Detection Limitations

The current detection has several limitations.

### Authentication failures only

The detection focuses on failed password authentication events.

It does not determine whether an attacker successfully authenticated.

### Syslog dependency

The detection depends on SSH authentication events being correctly generated and ingested into Microsoft Sentinel.

### IPv4 extraction

The current regular expression extracts IPv4 addresses from the Syslog message.

IPv6 addresses are not handled by the current extraction expression.

### GeoIP dependency

Geographic enrichment depends on the `GeoIP_List` Watchlist containing a matching network range.

Events without a matching geographic record will not appear in the final map.

### Geographic accuracy

GeoIP information is approximate and should be treated as contextual information rather than definitive attribution.

---

## 10. Detection Engineering Considerations

The current implementation intentionally separates the detection process into multiple queries:

```text
failed-ssh-logins.kql
        |
        v
attacker-ip-extraction.kql
        |
        v
geoip-enrichment.kql
        |
        v
ssh-attack-map.kql
```

This structure makes it easier to understand, test, and troubleshoot each stage independently.

The final query combines the required stages for the geographic visualization.

## Conclusion

The detection pipeline demonstrates how raw Linux authentication telemetry can be transformed into contextual security information using Microsoft Sentinel.

The implementation progresses from:

```text
Raw Syslog
    ↓
Failed SSH Authentication
    ↓
Source IP Extraction
    ↓
GeoIP Enrichment
    ↓
Attack Aggregation
    ↓
Geographic Visualization
```

This provides the foundation for monitoring SSH authentication activity and investigating repeated authentication failures within the SOC laboratory.
