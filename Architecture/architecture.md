# Architecture

## Overview

The laboratory implements a centralized security monitoring architecture using Microsoft Azure and Microsoft Sentinel.

A Debian(11)Linux virtual machine is used as the monitored endpoint. SSH authentication events are collected from the Linux system and forwarded to Microsoft Sentinel through Azure Monitor Agent and a Data Collection Rule.

The collected events are then analyzed using Kusto Query Language (KQL). Failed SSH authentication attempts are identified, attacker IP addresses are extracted from the logs, and the IP addresses are enriched with geographic information using a Microsoft Sentinel Watchlist.

The enriched data is finally visualized through a custom Microsoft Sentinel Workbook.

## Main Components

### Debian Linux Endpoint

The monitored endpoint is a Debian 11 virtual machine deployed in Microsoft Azure.

The VM provides the SSH service used to generate authentication events for the laboratory.

Relevant authentication logs are stored in:

```text
/var/log/auth.log

```

These logs contain successful and failed authentication activity generated by services such as SSH.

### OpenSSH

OpenSSH provides the SSH service on the Linux endpoint.

Failed authentication attempts generate messages similar to:

```text
Failed password for invalid user admin from <IP_ADDRESS>

```

These events contain the source IP address that can later be extracted and investigated.

### rsyslog

rsyslog acts as the Linux system logging service.

It processes authentication events generated by SSH and makes them available to Azure Monitor Agent.

In this laboratory, Azure Monitor Agent configures rsyslog to forward the relevant Syslog events to the local AMA endpoint.

### Azure Monitor Agent

Azure Monitor Agent (AMA) is installed on the Debian virtual machine.

Its role is to collect the configured Syslog events and forward them to Azure Monitor according to the associated Data Collection Rule.

### Data Collection Rule

The laboratory uses the following Data Collection Rule:

```text
DCR-.SOC-LAB

```

The rule is configured to collect authentication-related Syslog facilities:

```text
auth
authpriv

```

The collected data is sent to the Log Analytics workspace used by Microsoft Sentinel.

### Log Analytics

The Log Analytics workspace acts as the central storage and query layer for the collected security events.

Workspace:

```text
workspace-soc

```

The Linux authentication events are available through the `Syslog` table.

### Microsoft Sentinel

Microsoft Sentinel provides the SIEM capabilities used by the laboratory.

The collected events are analyzed using Kusto Query Language (KQL) to:

- Identify failed SSH authentication attempts.
- Extract attacker IP addresses.
- Count authentication failures.
- Enrich IP addresses with geographic information.
- Prepare data for visualization.

### GeoIP Watchlist

A Microsoft Sentinel Watchlist named:

```text
GeoIP_List

```

contains geographic IP range information generated from the IP2Location LITE database.

The Watchlist contains fields including:

```text
network
country
region
city
latitude
longitude

```

The `network` field contains IPv4 CIDR ranges used by the `ipv4_lookup()` operator.

This allows newly observed attacker IP addresses to be enriched automatically without manually adding each attacker IP to the Watchlist.

### Sentinel Workbook

A custom Microsoft Sentinel Workbook visualizes the enriched authentication events.

The map uses:

- Attacker IP
- Latitude
- Longitude
- Country
- City
- Failure count

This provides a geographic representation of SSH authentication activity observed by the laboratory.

## Security Considerations

The virtual machine is intentionally used as a monitored laboratory endpoint and may receive unsolicited SSH authentication attempts when exposed to the Internet.

The environment should therefore be treated as an isolated security laboratory.

The repository must not contain:

- SSH private keys.
- Passwords.
- Azure credentials.
- API keys.
- Access tokens.
- Subscription secrets.
- Sensitive personal information.

The GeoIP database itself is not included in the repository. Only the conversion script and documentation are stored.
